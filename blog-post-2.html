hreflang for European websites: the mistakes that cost rankings

The most common hreflang mistakes on multilingual European websites and how to fix them.

Nadeem Mayo 22 October 2026 3 min read

hreflang tells search engines which language and country each version of a page is meant for. On European sites with several languages it is one of the most valuable and most frequently broken technical signals.

1. Missing return links

Every page must reference all its alternates, and each alternate must reference it back. One missing link and search engines may ignore the set.

2. Wrong codes

Use ISO language codes, optionally with region: de, de-AT, fr-BE. Codes such as en-EU are not valid region codes.

3. Pointing to redirected or non-canonical URLs

hreflang should point to the final, canonical, indexable URL of each version.

4. Automatic redirects by IP or browser language

Forcing visitors to a version without letting them switch can stop search engines from seeing all versions. Offer a clear language switch instead.

Check it: crawl your site and compare the hreflang sets on a sample of pages in each language. Errors usually repeat across templates, so fixing one template fixes hundreds of pages.
